# Отключение лишних сервисов на роутере

Отключены неиспользуемые сервисы для чистоты системы, снижения паразитной нагрузки на CPU
(под трафиком) и приватности (убрана телеметрия наружу). Все сервисы отключены через
`disable` (убраны из автозапуска) + `stop` — пакеты не удалены, при желании легко вернуть.

---

## Контекст (важно для верных ожиданий)

На момент отключения CPU роутера был загружен на ~3% (97% idle) — то есть острой проблемы
производительности не было. Отключение сервисов не даёт прироста «в разы». Реальный эффект:

- под активной нагрузкой netifyd/gl_dpi не отъедают CPU на инспекцию трафика (польза для
  скорости туннеля на высоких скоростях);
- убрана телеметрия GL.iNet наружу (приватность);
- меньше процессов, чище система.

Это гигиена и приватность, а не революция в скорости. Туннель упирается в CPU при расшифровке —
это физический потолок MT5000, отключением сервисов не меняется.

---

## Отключённые сервисы

| Сервис     | За что отвечал                                                                                                                                               | Почему отключён                                                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `netifyd`  | DPI-агент (Deep Packet Inspection): инспектирует трафик пакет за пакетом, определяет, какое приложение его создало — для статистики приложений в GUI GL.iNet | Статистика не используется; под нагрузкой ест CPU; инспекция трафика не нужна                                                                           |
| `gl_dpi`   | Надстройка GL.iNet над DPI: классификация трафика + телеметрия                                                                                               | Не используется; телеметрия не нужна                                                                                                                    |
| `gl-cloud` | Связь с облаком GL.iNet: удалённое управление роутером через серверы GL.iNet + телеметрия наружу                                                             | Удалённый доступ не используется (замена — [WireGuard-сервер на роутере](18-wireguard-server.md)); телеметрия на серверы GL.iNet не нужна (приватность) |
| `zerotier` | Mesh-VPN (одноранговая сеть), альтернатива Tailscale                                                                                                         | Дублирует VPN-функциональность роутера; не используется                                                                                                 |
| `minidlna` | DLNA-медиасервер: раздача видео/музыки с USB-накопителя на устройства в сети (ТВ, плееры)                                                                    | Медиа с роутера не раздаётся                                                                                                                            |
| `tor`      | Tor-сервис (луковая маршрутизация)                                                                                                                           | Tor не используется; свой VPN-туннель уже есть                                                                                                          |

`samba4` (файловый сервер) уже был выключен ранее — не трогали.

---

## Что не отключалось (критично для работы)

Эти сервисы оставлены — они нужны:

- `mtkhnat` — аппаратный NAT MediaTek (ускоряет прямой РФ-трафик, разгружает CPU для туннеля);
- Xray (`xray-tproxy`) — сам VPN-туннель;
- AdGuard Home — DNS-резолвер + блокировка рекламы;
- dnsmasq — DNS на :53 (форвардит в AdGuard);
- nginx / uhttpd — веб-панель управления роутером;
- chronyd — синхронизация времени (важно для TLS/Reality).

---

## Как вернуть сервис (если однажды понадобится)

Включить обратно (маловероятно, но на всякий случай):

```sh
/etc/init.d/<сервис> enable
/etc/init.d/<сервис> start
```

Например, вернуть minidlna для раздачи медиа:

```sh
/etc/init.d/minidlna enable
/etc/init.d/minidlna start
```

Проверить статус:

```sh
/etc/init.d/<сервис> enabled && echo "включён" || echo "отключён"
```

## Проверка после отключения (выполнена)

- Все 6 сервисов не запущены и убраны из автозапуска (переживут перезагрузку отключёнными).
- Xray, интернет, туннель (заграничные сайты), РФ-сайты, веб-панель роутера — работают.
- CPU: 97% idle (как и было — сервисы простаивали в покое).

Отключение проводилось по одному с проверкой связи после каждого — чтобы точно знать, что ни
один не критичен. Ни один сбоя не вызвал.
