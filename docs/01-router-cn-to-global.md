# GL-MT5000 (Brume 3): перевод CN → Global

Снятие китайской региональной блокировки (country code `CN` → `US`) для разблокировки
VPN-функций и AdGuard Home в GUI и переключения firmware-канала на глобальный.

Инструкция составлена по факту реально пройденной процедуры на устройстве:

- Модель: GL.iNet GL-MT5000 (Brume 3), SoC MediaTek MT7987 (mt798x), eMMC 8 GB
- Прошивка: GL.iNet 4.8.6 (OpenWrt 21.02-SNAPSHOT, kernel 5.4.281)
- Управляющая машина: macOS

---

## ⚠️ Предупреждения

- Процедура **не поддерживается официально** GL.iNet, аннулирует гарантию и при
  ошибке может привести к кирпичу. Раскирпичивание не гарантировано.
- MT5000 **отсутствует** в списке протестированных моделей скрипта (там MT3000 /
  MT6000 / XE3000). На этом устройстве процедура прошла успешно, но действия
  выполняются на свой риск.
- Шаг с бэкапом factory-раздела **обязателен**. Без него откат может быть невозможен.
- `firstboot` в конце **сотрёт всё** — все настройки, пакеты, конфиги. Переустановка
  стека (sing-box, AdGuard Home и т.д.) потребуется с нуля.

---

## Ключевые факты об устройстве (для понимания, что делаем)

- Country code **не** хранится в UCI / `/etc/config/wireless` — там пусто.
- `/proc/mtd` пустой: это eMMC, а не MTD-флеш. Поэтому методы для NOR/NAND не работают.
- Реальное место хранения подсказывает device tree:
  `/sys/firmware/devicetree/base/gl-hw/factory_data/country_code` → указывает на
  раздел `/dev/mmcblk0p2`, offset `0x4088`.
- По offset `0x4088` лежат 2 байта: `43 4E` = `CN` (нужно заменить на `55 53` = `US`).
- Раздел `/dev/mmcblk0p2` имеет PARTLABEL `factory` (это важно для скрипта).
- Маркеры валидного factory-раздела: строки `firsttest` и `secondtest`.
- Значение читается в рантайме через `/proc/gl-hw-info/country_code`.

## Шаг 0. Доступ по SSH

Подключиться к роутеру (по умолчанию LAN-адрес `192.168.8.1`):

```sh
ssh root@192.168.8.1
```

Пароль — тот, что задан в админ-панели.

---

## Шаг 1. Диагностика (подтвердить, что лок именно CN и где он лежит)

```sh
cat /etc/glversion
cat /proc/gl-hw-info/country_code
find /sys/firmware/devicetree/base/gl-hw/factory_data -type f
```

`country_code` должен вернуть `CN`. Подтвердить физическое расположение и значение:

```sh
dd if=/dev/mmcblk0p2 bs=1 skip=$((0x4088)) count=2 2>/dev/null | hexdump -C
```

Ожидаемо: `43 4e  |CN|`. Значение offset для дальнейших шагов: `0x4088` (= 16520 в десятичном).

Проверить, что раздел определяется по метке (это решает, сработает ли автопоиск скрипта):

```sh
blkid -t PARTLABEL="factory" -o device
```

Должно вернуть `/dev/mmcblk0p2`. Если вернёт пусто — автопоиск скрипта не сработает
(см. раздел «Если blkid не находит раздел»).

---

## Шаг 2. Бэкап factory-раздела

Сделать полную копию раздела (4 MiB):

```sh
dd if=/dev/mmcblk0p2 of=/root/factory_full.img bs=2M
```

Проверить целостность прямо на роутере:

```sh
ls -lh /root/factory_full.img
strings /root/factory_full.img | grep -E "firsttest|secondtest"
```

Размер ~4.0M; обе строки должны найтись.

---

## Шаг 3. Вытащить бэкап на компьютер

> ⚠️ `/root` будет стёрт `firstboot`. Бэкап **обязательно** скопировать наружу
> до финального сброса.

На современных macOS / OpenSSH 9+ `scp` по умолчанию работает через SFTP, которого
на роутере нет (ошибка `sftp-server: not found`). Решение — флаг `-O` (заглавная O),
переключающий на legacy-протокол SCP. Команда выполняется **на компьютере**:

```sh
scp -O root@192.168.8.1:/root/factory_full.img ./
```

Надёжный запасной способ (не зависит от scp/sftp):

```sh
ssh root@192.168.8.1 "cat /root/factory_full.img" > factory_full.img
```

---

## Шаг 4. Проверить бэкап на компьютере

```sh
ls -lh factory_full.img
```

Размер должен быть ровно **4194304 байт** (4 MiB).

> Грабли macOS: если `grep` подменён на `ripgrep`, флаг `-E` означает «кодировка»,
> а не «regex». Решение — один из вариантов:

```sh
strings factory_full.img | grep -a "firsttest\|secondtest"
# или в обход алиаса:
command grep -E "firsttest|secondtest" <(strings factory_full.img)
```

Опционально — проверить, что country code в бэкапе именно `CN`:

```sh
dd if=factory_full.img bs=1 skip=$((0x4088)) count=2 2>/dev/null
```

Должно вывести `CN`. Только после подтверждения целого бэкапа двигаться дальше.

## Шаг 5. Скрипт снятия лока

Скрипт уже включён в этот репозиторий: `scripts/third_party/glinet-remove-chinalock.sh`.

Это зафиксированная, проверенная версия (2024.05.19.02) с одним отличием от
оригинала: отключено автообновление скрипта из интернета (в оригинале скрипт при
запуске сам скачивает свежую версию с GitHub и подменяет себя ей — в этой копии
эта строка закомментирована, чтобы использовалась ровно та версия, которая уже
проверена и описана в этой инструкции, а не произвольная более новая).

Автор скрипта — Admon (GitHub: Admonstrator), оригинальный репозиторий:
`github.com/Admonstrator/glinet-remove-chinalock`. Использованная копия взята из
форка `github.com/Oasis-2023/glinet-remove-chinalock` — на момент подготовки этой
инструкции прямая ссылка на оригинал отдавала 404, форк содержал тот же код.

Скопировать скрипт на роутер (команда на компьютере):

```sh
scp -O scripts/third_party/glinet-remove-chinalock.sh root@192.168.8.1:/tmp/
```

Перед запуском рекомендуется прочитать сам скрипт — он не длинный и полностью
открыт для просмотра в этом репозитории.

Посмотреть справку:

```sh
sh /tmp/glinet-remove-chinalock.sh --help
```

## Шаг 6. Запуск

```sh
sh /tmp/glinet-remove-chinalock.sh --new-country-code=US
```

Подтвердить `y` на предупреждении.

Что делает скрипт (по шагам лога):

1. Находит factory-раздел по метке → `/dev/mmcblk0p2`.
2. Делает собственный бэкап в `/root/factory_partition_<дата>.img` и проверяет
   в нём `firsttest` / `secondtest`.
3. Ищет country code двумя паттернами. Первая попытка `FF434E` на MT5000 **не
   находит** (перед `CN` идут нули, не `FF`) — это нормально. Вторая попытка
   `00434E` находит код по offset 16520 (= `0x4088`).
4. Записывает новый код `US` (`55 53`) поверх `CN`.

Про код страны: MT5000 — проводной шлюз, Wi-Fi обычно раздаёт отдельная точка
(MikroTik и т.п.), поэтому реальный Wi-Fi regdomain роли не играет. Код влияет на
разблокировку VPN/AdGuard в GUI и на переключение firmware-канала с `.cn` на `.com`.
`US` — самый обкатанный вариант.

---

## Шаг 7. Проверить запись ДО сброса (критично)

```sh
dd if=/dev/mmcblk0p2 bs=1 skip=$((0x4080)) count=24 2>/dev/null | hexdump -C
```

По offset `0x4088` должно стоять `55 53` (= `US`). Пример корректного вывода:

```
00000000  00 00 00 00 00 00 00 00  55 53 00 00 00 00 00 00  |........US......|
```

> Примечание: команда `dd ... | <без hexdump>` может не показать `US` перед
> промптом из-за непечатаемых соседних байтов — это артефакт терминала. Достоверен
> именно hex-вывод. Если на `0x4088` стоит `55 53` — запись прошла.

```sh
firstboot
```

Подтвердить `y`, затем:

```sh
reboot
```

## Шаг 9. Проверка после перезагрузки

1. Зайти в веб-панель `192.168.8.1`, пройти первичную настройку.
2. В боковом меню должны появиться разделы **VPN** и **AdGuard Home** —
   визуальное подтверждение снятия CN-lock.
3. В SSH:

```sh
cat /proc/gl-hw-info/country_code
```

Должно вернуть `US`. GL-сервисы (`gl-dpi`, `gl-cloud`) теперь ходят на
`firmware-api.gl-inet.com` вместо `.cn`.

## Восстановление (откат на CN / спасение)

Суть отката: записать сохранённый `factory_full.img` обратно в `/dev/mmcblk0p2`.

### Сценарий 1 — ОС грузится, SSH работает (самый частый)

Залить бэкап обратно на роутер (команда на компьютере):

```sh
scp -O factory_full.img root@192.168.8.1:/tmp/
# либо: cat factory_full.img | ssh root@192.168.8.1 "cat > /tmp/factory_full.img"
```

На роутере проверить и записать:

```sh
strings /tmp/factory_full.img | grep -E "firsttest|secondtest"
dd if=/tmp/factory_full.img of=/dev/mmcblk0p2 bs=2M conv=notrunc
sync
reboot
```

`conv=notrunc` обязателен — пишем поверх, не обрезая раздел.

### Сценарий 2 — ОС не грузится нормально (failsafe)

OpenWrt failsafe поднимает минимальную среду с SSH (обычно на `192.168.1.1`,
root без пароля). Точная комбинация входа для MT5000 — в официальном debrick-гайде:
`https://docs.gl-inet.com/router/en/4/faq/debrick/`. В failsafe смонтировать раздел
и повторить `dd` из Сценария 1.

### Сценарий 3 — полный кирпич (U-Boot recovery)

U-Boot recovery восстанавливает **прошивку**, но НЕ трогает factory-раздел. То есть
спасает ОС, но не возвращает factory-данные из `.img`. Порядок: сначала U-Boot
recovery (зажать reset при включении → зайти на `192.168.1.1` → залить Global-
прошивку), получить обратно SSH, затем залить factory-бэкап по Сценарию 1.
Процедура recovery — в том же debrick-гайде.

## Приложение: краткая шпаргалка

| Параметр            | Значение                                                                                                    |
| ------------------- | ----------------------------------------------------------------------------------------------------------- |
| Раздел factory      | `/dev/mmcblk0p2` (PARTLABEL `factory`)                                                                      |
| Offset country code | `0x4088` (= 16520 dec)                                                                                      |
| CN (исходно)        | `43 4E`                                                                                                     |
| US (целевое)        | `55 53`                                                                                                     |
| Размер раздела      | 4 MiB (4194304 байт)                                                                                        |
| Маркеры валидности  | `firsttest`, `secondtest`                                                                                   |
| Рантайм-значение    | `cat /proc/gl-hw-info/country_code`                                                                         |
| Скрипт              | `scripts/third_party/glinet-remove-chinalock.sh` в этом репозитории (автор: Admon, github.com/Admonstrator) |

### Если blkid не находит раздел (на будущее / другие прошивки)

Если `blkid -t PARTLABEL="factory"` вернёт пусто, автопоиск скрипта упадёт. Тогда
country code можно заменить вручную по известному offset (только при наличии
проверенного бэкапа!):

```sh
printf '\x55\x53' | dd of=/dev/mmcblk0p2 seek=$((0x4088)) bs=1 count=2 conv=notrunc
sync
```

После — `firstboot` + `reboot`, как в основной процедуре.
