# xray-route — управление исключениями маршрутизации

Скрипт для добавления/удаления сайтов-исключений в маршрутизации Xray на MT5000.
Позволяет вручную переопределять, какой сайт идёт через туннель (VPN), а какой — напрямую.

Расположение: `/opt/xray/xray-route.sh`, симлинк `/usr/bin/xray-route`.
В этом репозитории: `scripts/03-xray-route.sh`.

---

## Зачем нужен

Базовая логика роутера (smart-ru): российские сайты (`.ru`, geoip:ru) идут **напрямую**,
всё остальное — **через туннель**. Иногда нужны исключения:

- **РФ-сайт через туннель** — например сайт заблокирован для РФ-адресов, но в зоне `.ru`,
  поэтому по базовому правилу шёл бы напрямую и не открывался. Добавляем в proxy-исключения.
- **Заграничный сайт напрямую** — например сервис, который блокирует VPN или лучше работает
  с российским IP. Добавляем в direct-исключения.

Исключения имеют **высший приоритет** — перекрывают базовую smart-ru логику.

---

## Команды

Короткий вызов (через симлинк `/usr/bin/xray-route`) — работает из любого места:

```sh
xray-route add-proxy  <домен>   # сайт через туннель (VPN)
xray-route add-direct <домен>   # сайт напрямую (мимо VPN)
xray-route del        <домен>   # удалить сайт из исключений
xray-route list                 # показать все исключения
```

Полный путь (то же самое): `sh /opt/xray/xray-route.sh <команда>`

---

## Примеры

Открыть заблокированный РФ-сайт через туннель:

```sh
xray-route add-proxy example.ru
```

Пустить заграничный сайт напрямую:

```sh
xray-route add-direct example.com
```

Сайт сменил домен (частая история для заблокированных сервисов) — удалить старый,
добавить новый:

```sh
xray-route del example.ru
xray-route add-proxy example2.ru
```

Посмотреть, что сейчас в исключениях:

```sh
xray-route list
```

## Как это работает (безопасность)

Каждая команда изменения:

1. делает бэкап конфига;
2. правит `client.json` через `jq` (JSON редактируется как структура — не ломается);
3. валидирует результат через `xray -test`;
4. при успехе — перезапускает сервис `xray-tproxy`;
5. **при любой ошибке — автоматически откатывает** конфиг из бэкапа.

То есть сломать рабочую схему скриптом нельзя — если что-то не так, он вернёт как было.

Домен нормализуется автоматически: можно вводить с `https://`, с путём, в любом регистре —
скрипт приведёт к чистому виду (например `HTTPS://Example.ru/page` в `example.ru`).

Один домен не может быть одновременно в proxy и direct: при добавлении в один список
скрипт уберёт его из другого.

## Технические детали

- Исключения хранятся в `client.json`, в двух правилах routing с метками
  `ruleTag: user-proxy` и `ruleTag: user-direct`, стоящих **выше** базовых правил.
- В каждом правиле есть домен-заглушка (`placeholder-*.invalid`) — он нужен, чтобы правило
  было валидным даже без реальных доменов (Xray не принимает пустые правила).
  Заглушки не отображаются в `list` и ни на что не влияют (зона `.invalid` не существует).
- Симлинк `/usr/bin/xray-route` то есть `/opt/xray/xray-route.sh` лежит на overlay-разделе,
  поэтому **переживает перезагрузку** — короткий вызов доступен всегда.

---

## Если что-то пошло не так

Скрипт сам откатывается при ошибке, но если нужно вручную вернуть последний бэкап:

```sh
cp /tmp/xray-route-backup.json /opt/xray/config/client.json
/etc/init.d/xray-tproxy restart
```

(бэкап `/tmp/...` живёт до перезагрузки; постоянный рабочий бэкап —
`/opt/xray/backup/client.json.working`)
