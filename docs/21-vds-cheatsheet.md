# VDS — шпаргалка по повседневной работе

Компаньон к [«VDS — базовый хардненинг»](03-vds-hardening.md): там — защита сервера,
здесь — рутинные операции при повседневной эксплуатации (подключение, Docker,
обновления, диагностика «всё пропало»).

> Плейсхолдеры: `<alias>` — короткое имя сервера из `~/.ssh/config` (см.
> [«SSH-ключи и подключения»](01-ssh-keys-and-connections.md)), `<SERVER_IP>` — IP сервера.

---

## Подключение

```
ssh <alias>            # вход на сервер по ключу (пароль не спросит — Keychain)
```

Алиас настроен в `~/.ssh/config` и включает автоматический туннель к веб-панели.

Запасной путь (если ключ недоступен):

```
ssh root@<SERVER_IP>   # вход по паролю
```

## Веб-панель wg-easy

Панель не доступна из интернета — только через SSH-туннель (см. [«VDS — базовый
хардненинг»](03-vds-hardening.md), закрытие панели от внешнего доступа):

```
ssh <alias>                          # подключиться (туннель поднимется сам)
# оставить окно открытым, в браузере:
http://localhost:51821
```

Туннель живёт, пока открыта SSH-сессия. Закрыл окно — панель перестала открываться, это норма.

## Копирование файлов

```
scp -O <файл> <alias>:/path/          # на сервер (флаг -O для новых macOS)
scp -O <alias>:/path/<файл> ~/        # с сервера
```

## Обслуживание

### Docker-контейнеры

```sh
docker ps                                              # что запущено
docker ps --format "table {{.Names}}\t{{.Status}}"     # кратко
docker logs <контейнер> --tail 50                      # логи контейнера
docker restart <контейнер>                             # перезапустить
```

### Firewall

```
ufw status verbose        # текущие правила
ufw allow <port>/<proto>  # открыть порт
ufw delete allow <port>   # закрыть порт
```

### fail2ban

```
fail2ban-client status sshd            # забаненные IP, статистика
fail2ban-client set sshd unbanip <IP>  # разбанить (если случайно себя)
```

### Обновления

```
apt update && apt upgrade -y
[ -f /var/run/reboot-required ] && echo "нужен reboot"
```

### Проверка портов наружу

```
ss -tulnp | grep -v "127.0.0.1\|::1"   # что слушает на внешних интерфейсах
```

## Пересоздание контейнера с портом на localhost (образец)

Если нужно закрыть веб-порт какого-то контейнера от интернета (Docker пишет
правила в iptables в обход ufw — механика разобрана в [«VDS — базовый
хардненинг»](03-vds-hardening.md)):

```
# бэкап данных (если на хосте bind-mount)
tar czf /root/<контейнер>-backup-$(date +%Y%m%d).tar.gz /path/to/data

docker stop <контейнер> && docker rm <контейнер>

docker run -d --name=<контейнер> \
  ... (прежние параметры: -e, -v, --network, --cap-add, --restart) ... \
  -p <public-port>:<port>/udp \
  -p 127.0.0.1:<web-port>:<web-port>/tcp \   # веб — только localhost
  <image>
```

Данные в bind-mount (`-v /host/path:/container/path`) при пересоздании сохраняются.

## Диагностика «всё пропало»

**Не заходит по SSH с рабочей машины:**

- ключ в агенте? `ssh-add -l` (если пусто: `ssh-add --apple-use-keychain ~/.ssh/id_ed25519_servers`)
- сервер жив? проверить через панель хостера (ping/консоль)
- случайно забанил себя fail2ban? — зайти через консоль хостера, `fail2ban-client set sshd unbanip <IP>`

**Панель не открывается:**

- SSH-сессия с туннелем открыта? Без неё localhost-порт не слушается — это норма.

**VPN не работает у клиентов:**

- контейнеры живы? `docker ps`
- порты открыты? `ufw status` (443 для Xray, 51820/udp для WireGuard)
- Xray-контейнер: `docker logs xray... --tail 30`

## Резервные копии (важно!)

Что стоит держать в надёжном месте (менеджер паролей / зашифрованный архив):

- **приватный SSH-ключ** `~/.ssh/id_ed25519_servers` — без него доступ по ключу теряется
  при потере рабочей машины (останется только пароль через плохую консоль хостера);
- пароль root (в менеджере паролей);
- параметры запуска контейнеров (`docker run ...` или compose-файлы).

Данные wg-easy на сервере: `/root/.wg-easy` (bind-mount) — там конфиги WG-клиентов.
