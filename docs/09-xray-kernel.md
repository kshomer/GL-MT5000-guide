# xray-kernel — смена версии ядра Xray

Скрипт для безопасной смены версии Xray-core на роутере MT5000.
Скачивает версию с GitHub, проверяет, ставит, при неудаче откатывает.

Расположение: `/opt/xray/xray-kernel.sh`, симлинк `/usr/bin/xray-kernel`.
В этом репозитории: `scripts/05-xray-kernel.sh`.

---

## Команды

```sh
xray-kernel update <версия>   скачать и поставить версию (напр. update 26.6.22)
xray-kernel rollback          откат на предыдущую версию
xray-kernel show              показать текущую версию и версию в бэкапе
```

Версию вводить числом, без `v` (например `26.6.22`). Скрипт сам добавит `v` для URL.

Где смотреть версии: https://github.com/XTLS/Xray-core/releases
(важно: именно releases — там бинарные архивы. Страница pkgs/container — это Docker-образы
для сервера, не для роутера.)

---

## Примеры

Поставить конкретную версию:
```sh
xray-kernel update 26.6.22
```

Посмотреть, что стоит сейчас:
```sh
xray-kernel show
```

Откатиться, если новая версия повела себя плохо:
```sh
xray-kernel rollback
```

---

## Что делает при update (безопасность)

1. скачивает бинарь нужной версии с GitHub (arm64);
2. проверяет размер архива, распаковывает только бинарь;
3. запускает новый бинарь: `version` (не битый?) + `-test` с боевым конфигом (совместим?);
4. если проверки не прошли — НЕ трогает рабочую версию, выходит;
5. бэкапит текущий бинарь в `xray.backup`;
6. ставит новый, перезапускает сервис;
7. **активная проверка туннеля**: поднимает временное соединение через сервер и проверяет
   реальный доступ (google). Если туннель не поднялся — делает повторный restart и проверяет
   снова (до 3 попыток);
8. если после 3 попыток туннеля нет — **автооткат** на предыдущую версию.

geodata скрипт НЕ трогает (она независима от версии ядра).

---

## Про активную проверку туннеля

Скрипт не говорит «готово», пока реально не убедится, что трафик идёт через сервер.
Это защищает от ситуации, когда Xray запущен, но туннель не поднялся. Если проверка видит,
что туннель не отвечает — сама пробует ещё раз (restart). В выводе видно процесс:
`Проверка туннеля... Туннель работает` или `Туннель пока не отвечает... Повторный перезапуск`.

---

## Про паузу и прогрев

Каждая операция завершается только после подтверждения работы туннеля. Дополнительно ждать
не нужно — скрипт сам дожидается. Если появилось сообщение «Туннель работает» — можно
пользоваться сразу.

---

## Если что-то пошло не так

Ручной откат:
```sh
xray-kernel rollback
```

Если и это не помогло (крайний случай):
```sh
/etc/init.d/xray-tproxy restart
```
и подождать ~30 секунд.

---

## Резервный бинарь

Скрипт хранит один уровень отката — предыдущий рабочий бинарь в `/opt/xray/bin/xray.backup`.
Версию в бэкапе всегда можно посмотреть через `xray-kernel show`.
