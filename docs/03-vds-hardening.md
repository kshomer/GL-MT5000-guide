# VDS — базовый хардненинг (защита сервера)

На сервер уже установлен Xray, wg-easy и Telegram-прокси в Docker.

Настройка безопасности VPS, на котором крутятся VPN-сервисы (Xray, wg-easy и
Telegram-прокси) в Docker. Цель — настройка базовой защиты сервера и настройка
удобного и безопасного доступа. Ubuntu 24.04 LTS.

> Секреты (IP, ключи, пароли, хостнеймы) в документе не приводятся — только методика.
> Плейсхолдеры: `<SERVER_IP>`, `<HOME_IP>`, порты сервисов условны.

---

## Исходное состояние ВДС до настройки

Аудит публично доступного сервера выявил:

- **firewall выключен** (ufw inactive) — все слушающие порты открыты в интернет;
- **веб-панель wg-easy открыта наружу** (порт 51821, HTTP без TLS) — технически любой мог открыть её
  и подбирать пароль; при этом Docker пробрасывал порт в обход любого firewall;
- **~20000 неудачных попыток входа** по SSH в логах — сервер под постоянным брутфорсом ботами;
- **вход root по паролю разрешён**, fail2ban не установлен;
- система с непоставленными обновлениями.

## Что сделано

### 1. SSH-доступ по ключу (ed25519)

На рабочей машине сгенерирован отдельный ключ для серверов:

```sh
ssh-keygen -t ed25519 -C "<comment>" -f ~/.ssh/id_ed25519_servers
```

Ключ защищён passphrase. На macOS passphrase сохранён в Keychain — вводится один раз:

```sh
ssh-add --apple-use-keychain ~/.ssh/id_ed25519_servers
```

Публичный ключ скопирован на сервер:

```sh
ssh-copy-id -i ~/.ssh/id_ed25519_servers.pub root@<SERVER_IP>
```

### 2. Удобные алиасы (~/.ssh/config на рабочей машине)

```ini
Host *
    UseKeychain yes
    AddKeysToAgent yes

Host <alias-server>
    HostName <SERVER_IP>
    User root
    IdentityFile ~/.ssh/id_ed25519_servers
    LocalForward 51821 localhost:51821    # авто-туннель к веб-панели

Host <alias-router>
    HostName <ROUTER_IP>
    User root
    IdentityFile ~/.ssh/id_ed25519_servers

Host github github.com
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519        # отдельный ключ для GitHub
```

Вместо `<alias-server>` и `<alias-router>` используются удобные имена для сервера и роутера.
Теперь подключение — короткой командой, вход без ввода пароля (Keychain), а к серверу
сразу поднимается туннель к панели.

### 3. Firewall (ufw)

Политика по умолчанию — запретить входящее, разрешить исходящее. Открыты только нужные порты:

```sh
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp        # SSH
ufw allow 443/tcp       # Xray (VLESS+Reality)
ufw allow 51820/udp     # wg-easy
ufw allow <other>/tcp   # прочие нужные сервисы
ufw --force enable
```

Веб-панель (51821) НЕ открывается — доступ только через SSH-туннель (см. ниже).

### 4. Закрытие веб-панели wg-easy (обход Docker → ufw)

**Проблема:** Docker пишет правила напрямую в iptables (цепочка DOCKER), ДО ufw. Порт,
проброшенный контейнером на `0.0.0.0`, остаётся доступен снаружи даже при закрытом ufw.

**Решение:** привязать порт панели только к localhost. Контейнер пересоздан с изменённым
биндингом (данные wg-easy лежат на хосте в bind-mount, при пересоздании не теряются):

```
# было:  -p 51821:51821/tcp           (0.0.0.0 — наружу)
# стало: -p 127.0.0.1:51821:51821/tcp (только localhost)
```

Порт wg-easy (51820/udp) остался публичным — он нужен для VPN-клиентов.

**Доступ к панели после этого** — через SSH-туннель с рабочей машины:

```sh
ssh <alias-server>                     # алиас уже содержит LocalForward
# затем в браузере: http://localhost:51821
```

Снаружи панель недоступна вообще.

### 5. fail2ban (защита от брутфорса)

```sh
apt install -y fail2ban
```

Конфиг `/etc/fail2ban/jail.local`:

```ini
[DEFAULT]
ignoreip = 127.0.0.1/8 ::1 <docker-subnet>
bantime = 1h
findtime = 10m
maxretry = 5
bantime.increment = true     # повторным нарушителям срок растёт
bantime.factor = 2
bantime.maxtime = 7d

[sshd]
enabled = true
port = 22
backend = systemd
maxretry = 5
```

После 5 неудачных попыток с одного IP за 10 минут — бан на час, при повторах срок удваивается
(до 7 дней). Локальные адреса и Docker-сеть в белом списке. Сразу после запуска забанил
первую партию атакующих IP.

### 6. Обновления системы

```sh
apt update && apt upgrade -y
reboot    # если требуется (обновилось ядро/системные библиотеки)
```

Контейнеры с `--restart=unless-stopped` поднимаются автоматически после перезагрузки.

### 7. Решение по входу root

**На данном этапе оставлены оба способа: ключ + пароль.** Осознанный выбор для личного сервера.

Полное отключение пароля (`PasswordAuthentication no`) НЕ применено намеренно: на данном этапе
оставлены оба способа: ssh-ключ для удобства, пароль как запасной путь на всякий случай.
После проверки работоспособности и отсутствия проблем с доступом, можно будет отключить пароль.
Или же оставить как есть.

## Итоговая модель безопасности

| Слой                | Что даёт                                                      |
| ------------------- | ------------------------------------------------------------- |
| ufw                 | наружу открыты только необходимые порты                       |
| панель на localhost | веб-интерфейс не виден из интернета, только через SSH-туннель |
| fail2ban            | автоматический бан брутфорса SSH                              |
| SSH-ключ            | сильная аутентификация для повседневного доступа              |
| сложный пароль root | запасной путь, защищён fail2ban                               |
| обновления          | закрыты известные уязвимости                                  |

Было «дверь настежь» (панель наружу, ноль защиты, тысячи попыток подбора) → стало «крепко
и разумно» для личного сервера.
